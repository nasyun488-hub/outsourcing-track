# 外协工序流转追踪系统：全页面人机交互优化方案

日期：2026-06-16  
范围：除扫码录入页外的所有前端页面与主要功能  
约束：本方案只做交互/体验优化设计，不修改代码。

## 总体目标

把系统从“功能入口集合”优化为“按现场人员一天工作节奏组织的业务工作台”：

- 企业管理员：一眼看风险、查进度、处理异常、导出数据。
- 厂家管理员：关注本厂待接收/待发出/异常/逾期。
- 操作员：少判断、少查找、按提示完成接收/发出/退件。
- 管理员：人员、厂家、权限、申请审核流程清晰可控。

## 总体优化原则

1. **按人类任务流组织，而不是按数据库对象组织**  
   页面入口应围绕“今天要干什么”：待接收、待发出、异常、逾期、导出、通知。

2. **先给结论，再给明细**  
   每页顶部必须先告诉用户：现在有多少待处理、风险在哪里、下一步点哪里。

3. **减少页面跳转**  
   详情、操作、通知、筛选尽量用卡片、抽屉、底部弹层完成，减少“进一页、退一页”。

4. **移动端大按钮、大数字、少输入**  
   现场 H5 优先考虑单手操作、手套/油污环境、扫码枪键盘输入场景。

5. **异常不打断主流程，但必须可追踪**  
   异常集中成“异常队列”，提示原因、建议处理动作、责任角色。

# 1. 登录页优化方案

## 当前定位

登录页目前是手机号 + 验证码登录，功能可用，但对不同角色、演示环境、错误恢复提示不足。

## 优化目标

让用户快速进入系统，减少“验证码不知道去哪了 / 登录失败不知道为什么 / 登录后不知道自己是什么角色”的困惑。

## 建议交互

### 页面结构

- 顶部：系统名称 + 简短业务说明  
  `外协工序流转追踪｜扫码记录每一道流转`
- 中部：手机号输入 + 验证码输入
- 底部：
  - 登录按钮
  - 演示账号入口（如仅演示环境显示）
  - 常见问题：收不到验证码 / 更换手机号 / 联系管理员

### 输入体验

- 手机号自动格式化：`138 0013 8000`
- 验证码输入框 6 位自动提交可选。
- 发送验证码后倒计时展示明确：`58 秒后可重发`
- 错误提示要说人话：
  - 不要只说 `401`。
  - 应提示：`验证码已过期，请重新获取`、`该手机号未绑定厂家，请联系管理员`。

### 登录后体验

- 登录成功后 toast：`欢迎，张三｜A厂操作员`
- 首页顶部同步显示角色和厂家。

## 验收标准

- 空手机号、错误手机号、空验证码、错误验证码都有明确提示。
- 发送验证码后倒计时准确。
- 登录成功后能看出当前身份与所属厂家。

# 2. 首页 / 工作台优化方案

## 当前定位

首页已有快捷入口，但更像“菜单页”，还不够像“今日工作台”。

## 优化目标

打开首页后，用户无需思考，直接看到“今天最该处理什么”。

## 建议页面结构

### 顶部身份卡

显示：

- 当前用户：姓名
- 当前角色：企业管理员 / 厂家管理员 / 操作员
- 所属厂家：如 A厂
- 今日日期

### 今日待办区（首页核心）

按角色显示不同卡片：

#### 操作员

- 待接收 X 条
- 待发出 X 条
- 退件待处理 X 条
- 异常/逾期 X 条

主按钮：

- `开始扫码录入`
- `查看待接收`
- `查看待发出`

#### 厂家管理员

- 本厂进行中订单
- 本厂逾期工序
- 待审核/待解锁
- 本厂操作员今日录入量

#### 企业管理员

- 全部订单概览
- 异常订单
- 厂家逾期排行
- 今日新增流转记录

### 快捷操作区

保留现有入口，但按使用频率排序：

1. 扫码录入
2. 订单看板
3. 我的通知
4. 数据导出
5. 管理入口（有权限才显示）

### 异常提醒条

如果存在异常：

- 首页顶部出现红/橙色提醒条。
- 文案示例：`当前有 3 条逾期工序，请优先处理`。
- 点击进入异常筛选后的看板。

## 验收标准

- 不同角色首页内容不同。
- 用户一眼能看到自己的待办数量。
- 首页不是单纯菜单，而是“工作台”。

# 3. 订单看板页优化方案

## 当前定位

看板已有统计卡、状态筛选、订单列表，但仍偏“列表查询”，还可以更贴近业务调度。

## 优化目标

把看板变成“外协流转雷达”：快速找订单、看风险、看卡在哪个厂家/工序。

## 建议页面结构

### 顶部总览

展示 4 个核心指标：

- 全部订单
- 进行中
- 已逾期
- 今日有流转

建议优先显示“异常/逾期”，不要只显示正常统计。

### 筛选体验

现有筛选可优化为“快捷筛选 + 高级筛选”：

#### 快捷筛选 chips

- 全部
- 我厂相关
- 待我处理
- 已逾期
- 今日更新
- 即将超期

#### 高级筛选折叠

- 订单号
- 制件名
- 件号
- 厂家
- 工序
- 日期范围
- 状态

### 订单卡片优化

每张订单卡建议显示：

- 订单号 + 制件名
- 当前卡点：`当前在 A厂｜第2道 表面处理`
- 流转进度：`2/4 道工序完成`
- 数量状态：`已接收 80 / 已发出 50 / 待处理 30`
- 风险标签：逾期、退件、等待上道、等待下道
- 主操作：`查看工序流`

### 列表排序建议

默认排序不应只是创建时间，建议：

1. 逾期订单
2. 待当前用户处理
3. 今日有变化
4. 普通进行中
5. 已完成

## 验收标准

- 能 3 秒内找到“最危险订单”。
- 能一眼知道订单卡在哪个厂家/哪道工序。
- 筛选不需要输入厂家 ID，应该可选择厂家名。

# 4. 订单工序详情页优化方案

## 当前定位

订单详情页展示工序详情，但需要进一步变成“工序时间线”。

## 优化目标

让用户一眼看懂：这个零件从哪里来、现在在哪、下一步去哪、哪里卡住。

## 建议页面结构

### 顶部订单摘要

- 订单号
- 制件名 / 件号
- 总数量
- 当前状态
- 当前所在厂家/工序
- 是否逾期

### 工序时间线

用纵向时间线展示每道工序：

每道工序卡片显示：

- 工序序号 + 名称
- 承接厂家
- 状态：待接收 / 已接收 / 已发出 / 已完成 / 异常
- 数量：应收、已收、已发、退件
- 时间：接收时间、发出时间、停留时长
- 操作按钮：接收 / 发出 / 查看 / 退件

### 当前可操作工序突出

当前用户有权限处理的工序应突出：

- 高亮边框
- 文案：`轮到你处理`
- 主按钮：`立即接收` / `立即发出`

### 异常解释

如果某工序不可操作，不要只禁用按钮，要显示原因：

- `上道还未发出，暂不能接收`
- `本道未接收，暂不能发出`
- `下道已接收，本道已锁定`
- `无本厂权限`

## 验收标准

- 用户能从时间线看懂完整流转。
- 所有禁用按钮都有原因。
- 当前用户该做什么被明确突出。

# 5. 接收录入页优化方案

## 当前定位

接收页已有可接收数量卡片和“全部”按钮，但更像表单，还可以更像现场确认页。

## 优化目标

把“填写表单”变成“确认收货”：少输入、强校验、防误操作。

## 建议交互流程

1. 顶部大数字显示：`本次最多可接收 80`
2. 中部显示来源：
   - 上道厂家
   - 上道工序
   - 上道发出数量
3. 默认数量填全部可接收。
4. 操作员可改数量。
5. 点击“确认接收”。
6. 二次确认只在异常场景出现：
   - 数量小于可接收量很多
   - 手动输入非整数
   - 接收时间不是当前时间

## 数量控件建议

改成收银台式数量控件：

- `-` 数量 `+`
- `全部`
- `清零`
- 超量实时提示

## 信息提示建议

- 可接收 = 上道已发 - 本道已收
- 明确显示计算式，减少现场争议：  
  `可接收 80 = 上道已发 80 - 本道已收 0`

## 提交后体验

成功后不要只弹窗，建议：

- 显示成功卡片：`已接收 12 件`
- 下一步按钮：
  - `继续扫码`
  - `查看订单工序`
  - `继续接收下一批`

## 验收标准

- 默认数量正确。
- 超量实时拦截。
- 禁用原因明确。
- 成功后下一步路径清楚。

# 6. 发出录入页优化方案

## 当前定位

发出页已有可发出数量、退件按钮，但“发出”和“退件”属于不同心智，应更清楚区分。

## 优化目标

把发出页优化为“发货确认 + 异常退件”两个明确区域。

## 页面结构建议

### 顶部发货卡

- 本次最多可发出 X
- 当前已接收 Y
- 当前已发出 Z
- 剩余可发出 X

公式显示：  
`可发出 = 本道已接收 - 本道已发出`

### 发出区域

- 默认数量 = 可发出数量
- 数量可编辑
- 发出时间默认当前
- 主按钮：`确认发出`

### 退件区域

不要只放一个小按钮，建议单独卡片：

- 标题：异常退件
- 说明：`发现不良/数量异常时，将零件退回上道工序`
- 按钮：`发起退件`

退件弹窗优化：

- 退件数量
- 退件原因快捷选项：
  - 加工不良
  - 数量不符
  - 表面缺陷
  - 图纸/规格不符
  - 其他
- 备注输入
- 显示退回到哪个厂家/工序

## 验收标准

- 发出和退件心智清晰分离。
- 退件原因支持快捷选择。
- 退件前明确显示“退回到哪里”。

# 7. 记录查看页优化方案

## 当前定位

记录查看页展示接收、发出、退件记录，但偏流水表。

## 优化目标

让查看页成为“单道工序档案”：能追溯这道工序发生过什么。

## 建议页面结构

### 顶部状态卡

- 工序名称
- 厂家
- 当前状态
- 锁定状态
- 可接收 / 可发出

### 数量汇总卡

- 累计接收
- 累计发出
- 退入
- 退出
- 当前余量

### 时间线流水

把接收、发出、退件统一成一条时间线，而不是分散三个列表：

- 10:00 接收 30 件｜操作员张三
- 14:00 发出 20 件｜操作员李四
- 15:00 退件 5 件｜原因：表面缺陷

支持按类型筛选：全部 / 接收 / 发出 / 退件。

### 操作按钮

底部根据状态显示：

- 可接收：显示“接收”
- 可发出：显示“发出”
- 可退件：显示“退件”
- 不可操作：显示原因

## 验收标准

- 用户不用切换多个分组就能按时间追溯。
- 数量汇总和流水能互相对上。

# 8. 通知中心优化方案

## 当前定位

通知页有列表和全部已读，但还不够像“任务消息中心”。

## 优化目标

把通知从“消息列表”升级为“待办提醒中心”。

## 页面结构建议

### 顶部分类 Tab

- 全部
- 未读
- 待处理
- 异常
- 逾期
- 系统

### 通知卡片信息

每条通知显示：

- 类型标签：异常 / 逾期 / 流转 / 系统
- 标题
- 关联订单/工序
- 时间
- 是否已读
- 操作按钮：`去处理` / `查看详情`

### 批量操作

- 全部已读
- 清理已读
- 只看未读

### 跳转优化

通知点击后应直接跳到对应业务上下文：

- 订单通知 → 订单工序详情
- 工序通知 → 记录查看页
- 待接收/待发出 → 对应操作页
- 退件通知 → 退件相关记录

## 验收标准

- 未读和待处理明确区分。
- 通知点击后能直接到业务处理点。
- 已读不等于已处理，两个状态不能混淆。

# 9. 数据导出页优化方案

## 当前定位

导出页是日期 + 订单号 + 厂家的表单，功能够用但用户不知道会导出什么。

## 优化目标

把导出从“填条件碰运气”变成“预览后确认导出”。

## 建议流程

1. 选择导出模板。
2. 选择筛选条件。
3. 点击“预览数据”。
4. 显示预计导出条数、时间范围、厂家范围。
5. 点击“确认导出”。
6. 生成文件并提示下载。

## 导出模板建议

- 订单总览
- 工序流转明细
- 接收/发出批次明细
- 退件异常明细
- 厂家绩效/逾期统计

## 筛选优化

- 快捷日期：今天、本周、本月、近 30 天、自定义
- 厂家选择不要输入 ID，应选择厂家名称
- 状态多选：待处理、进行中、已完成、逾期

## 验收标准

- 导出前能看到预计条数。
- 导出的内容类型清晰。
- 空数据时不下载空 Excel，而是提示“当前条件无数据”。

# 10. 人员管理页优化方案

## 当前定位

人员管理页有角色筛选、新增人员、审核操作，但管理心智还可以更清楚。

## 优化目标

让管理员快速完成：查人、加人、停用、授权、审核。

## 页面结构建议

### 顶部统计

- 总人数
- 企业管理员
- 厂家管理员
- 操作员
- 待审核
- 已停用

### 快捷筛选

- 全部
- 待审核
- 已启用
- 已停用
- 按厂家
- 按角色

### 人员卡片

每人一张卡：

- 姓名
- 手机号
- 角色
- 所属厂家
- 状态
- 最近登录/最近操作时间
- 操作：编辑、停用、重置验证码/密码、查看权限

### 新增人员表单

优化为分步：

1. 基本信息：姓名、手机号
2. 角色选择
3. 厂家绑定
4. 权限确认

角色选择应附带说明：

- 企业管理员：可查看全部订单和基础资料。
- 厂家管理员：管理本厂人员和本厂订单。
- 操作员：只能扫码录入和查看本厂记录。

## 验收标准

- 管理员能看出每个人属于哪个厂家、什么角色、是否启用。
- 新增人员时不会选错角色/厂家。

# 11. 厂家管理页优化方案

## 当前定位

厂家管理页可以新增厂家、审核申请，但缺少厂家运营状态视角。

## 优化目标

厂家管理不只是维护名单，还要能看出厂家是否活跃、是否异常、是否逾期多。

## 页面结构建议

### 顶部统计

- 厂家总数
- 合作中
- 待审核
- 停用
- 当前有逾期的厂家

### 厂家卡片

每个厂家显示：

- 厂家名称
- 联系人 / 电话
- 状态
- 当前进行中订单数
- 当前逾期数
- 最近流转时间
- 操作：查看订单、编辑、停用、审核

### 新增厂家表单

建议字段：

- 厂家名称
- 联系人
- 联系电话
- 地址（可选）
- 工序能力标签（如机加工、热处理、表面处理）
- 备注

### 审核流程

审核不要只有通过/拒绝按钮，建议：

- 通过
- 拒绝并填写原因
- 要求补充资料

## 验收标准

- 管理员能知道哪些厂家有逾期风险。
- 审核拒绝必须有原因。
- 厂家不仅是静态名单，而是业务对象。

# 12. 全局导航与权限优化方案

## 问题

当前页面之间主要靠首页入口和返回按钮，缺少统一的“当前位置”和“下一步”。

## 建议

### 底部导航

移动端建议固定底部导航：

- 首页
- 扫码
- 看板
- 通知
- 我的

管理入口放到“我的/管理”中，按权限显示。

### 面包屑 / 返回逻辑

业务页返回不要简单 `router.back()`，应回到合理上下文：

- 接收/发出成功 → 回订单详情或扫码清单
- 通知进入详情 → 返回通知中心
- 看板进入详情 → 返回看板筛选状态

### 权限隐藏

无权限功能不应只点击后提示无权限，而应：

- 首页不显示无权限入口。
- 详情页显示“无本厂权限，仅可查看摘要”。

# 13. 全局错误、空状态、加载态优化方案

## 错误提示

所有接口错误统一转换成人话：

- 网络失败：`网络连接失败，请检查信号后重试`
- 登录过期：`登录已过期，请重新登录`
- 权限不足：`当前账号无权操作该工序`
- 数量超限：`数量不能超过可操作余量 X`

## 空状态

空状态不要只说“暂无数据”，要告诉下一步：

- 暂无待接收：`当前没有轮到你接收的工序`
- 暂无订单：`可调整筛选条件或联系企业管理员创建订单`
- 暂无通知：`有异常、逾期、流转提醒时会出现在这里`

## 加载态

- 列表加载用骨架屏。
- 提交按钮 loading 时禁止重复点击。
- 长时间请求超过 5 秒提示“仍在处理，请勿重复提交”。

# 16. 后续验收建议

实施后应按“人类任务流”验收，而不是只看接口 200：

1. 操作员从首页进入待接收 → 接收 → 返回下一步。
2. 操作员从扫码清单进入发出 → 成功后继续扫码。
3. 厂家管理员打开首页 → 找到逾期 → 进入订单详情 → 定位责任工序。
4. 企业管理员打开看板 → 筛选厂家 → 导出本月异常明细。
5. 通知中心点击逾期通知 → 直达对应订单/工序。
6. 管理员新增操作员 → 绑定厂家 → 登录后只看到本厂权限。
