## P3：当前业务痛点与现状分析

### 外协流转现有模式
- 多厂家间工序交接主要依赖纸质记录、口头传达、微信群拍照
- 进度信息分散在不同人员手中，没有统一视图

### 典型痛点
| 痛点 | 影响 |
|------|------|
| **漏记错记** | 交接时数量、时间、责任人记录不全，事后容易扯皮 |
| **进度黑盒** | 订单卡在哪道工序、停留多久、为什么卡住，全靠打电话问 |
| **异常发现慢** | 超期停留、返工退件等异常，往往等到交付前才发现 |
| **责任追溯难** | 出了质量问题，找不到哪道工序、谁经手、什么时间交接 |
| **统计分析难** | 各厂家效率、停留时长、异常率等数据无法量化分析 |

### 当前现状数据（行业参考）
- 人工交接记录准确率：约 80%~85%
- 异常平均发现时间：3~5 天
- 订单进度单次问询耗时：15~30 分钟/次

## P4：项目定位与建设目标

### 项目是什么
外协零件在多厂家之间实物流转的**扫码追踪工具**——用手机扫码完成每道工序的接收、发出，自动记录流转全链路。

### 核心建设目标
> **每道工序"来有影、去有踪"，流转全链路可追溯**

### 解决的核心业务问题
1. ✅ **解决进度黑盒问题**：订单走到哪一步实时可见
2. ✅ **解决异常发现慢问题**：超期自动标红、卡点自动识别
3. ✅ **解决责任追溯问题**：谁接收、谁发出、什么时间、多少数量，系统全留痕
4. ✅ **解决跨厂扯皮问题**：交接标准统一、操作有记录、数量有校验

## P5：系统核心能力（当前已实现）

| 能力模块 | 说明 |
|---------|------|
| 📱 **扫码快速录入** | 手机摄像头扫码即可完成接收、发出，10 秒完成交接 |
| 📊 **订单看板** | 每道工序状态、数量、停留时长、负责人一目了然 |
| 🎯 **卡点自动识别** | 系统自动标出"当前卡点"工序，一眼知道卡在哪 |
| ⚠️ **风险预警** | 超过 48 小时未处理的工序自动标红提醒，给出原因 |
| 🔐 **权限隔离** | 各厂家只能看到和操作本厂工序，数据安全隔离 |
| 🔑 **双登录模式** | 手机验证码登录 + 账号密码登录，满足不同场景 |
| 📝 **操作留痕** | 所有接收、发出、退件操作都有时间、人员、数量记录 |
| 🔔 **通知中心** | 风险预警、待办提醒主动推送，不用每天刷看板 |

## P6：开发重点与难点说明

### 重点 1：多厂家权限边界与数据隔离
- 业务挑战：A 厂不能操作 B 厂工序，同时又需要看到相邻工序的进度上下文
- 实现方案：后端统一权限判定，每个操作都校验 `当前用户厂家 == 工序所属厂家`

### 重点 2：流转数量一致性保障
- 业务挑战：发出数量不能超过接收数量，接收数量不能超过上游发出数量
- 实现方案：三层校验（前端输入校验 → 后端业务逻辑校验 → 数据库事务原子提交）

### 重点 3：超期/卡点识别逻辑
- 业务挑战：不同工序、不同状态的超期判定规则不同，还要区分"真卡点"和"正常等待"
- 实现方案：按工序状态、停留时长、可操作数量综合计算风险等级，只把真正卡住的工序标为卡点

### 重点 4：移动端 H5 适配与扫码体验
- 业务挑战：不同手机、不同浏览器、微信内置浏览器兼容性差异大
- 实现方案：统一 H5 技术栈、标准摄像头扫码 API、离线扫码导入兜底

## P7：系统可以发挥的作用

### 对业务部门
- 订单进度实时掌握，不用再打电话问
- 异常早发现、早处理，减少交付延误
- 流转数据自动沉淀，为后续优化提供依据

### 对协作厂家
- 交接标准统一，避免口头沟通误会
- 操作简单、上手快，不用复杂培训
- 本厂待办清晰可见，不用反复核对邮件/群消息

### 对管理层
- 全局看板一眼掌握所有订单状态
- 风险预判能力提升，从"事后救火"变"事前预防"
- 各厂家效率、异常率可量化，为供应商评价提供数据支撑

### 对质量追溯
- 出了质量问题，可以追溯到每道工序的经手人、时间、数量
- 返工退件全链路记录，质量问题闭环管理

## P8：外部对接与协调需求

### 🔹 IT 部门需协调事项
1. **服务器资源**：生产环境服务器 1 台（配置建议见下页）
2. **网络策略**：开放 8000（后端）、8081（前端）端口，配置域名与 HTTPS 证书
3. **账号对接**：如需对接现有企业账号体系，IT 需提供对接接口与文档
4. **数据备份**：配置数据库定期备份策略，保障数据安全
5. **运维支持**：上线后日常运维、故障排查、版本升级

### 🔹 协作厂家需协调事项
1. **操作培训**：每家试点厂家安排 1~2 名操作员参加培训（约 1 小时）
2. **扫码设备**：建议配备带摄像头的智能手机或专用扫码枪（现有手机即可用）
3. **基础数据确认**：确认厂家名称、工序名称、零件编号等基础数据的准确性
4. **试运行配合**：试点运行期间，按要求使用系统完成交接，及时反馈问题

### 🔹 其它协调
- 业务部门：指定 1 名对接人负责需求确认、问题协调
- 质量部门：如需质量追溯功能拓展，需提前明确追溯维度与要求

## P9：系统部署需求（生产环境）

### 服务器配置建议
| 配置项 | 建议规格 | 说明 |
|--------|---------|------|
| CPU | 4 核 | 并发量不大时 2 核也可运行 |
| 内存 | 8 GB | MySQL + 后端 + 前端同时运行 |
| 硬盘 | 100 GB SSD | 主要存储数据库与日志，每年增量约 10 GB |
| 操作系统 | Linux（推荐 Ubuntu 22.04 / CentOS 7+） | |

### 网络与端口要求
| 端口 | 用途 | 访问范围 |
|------|------|---------|
| 8081 | 前端 H5 页面 | 所有操作员手机/电脑可访问 |
| 8000 | 后端 API 服务 | 仅前端访问，不对外暴露 |
| 3306 | MySQL 数据库 | 仅内网运维访问，不对外暴露 |

### 安全与备份
- **HTTPS**：生产环境必须配置 HTTPS 证书，保障数据传输安全
- **数据备份**：数据库每日自动备份，备份保留 30 天
- **日志保留**：操作日志、接口日志保留 90 天
- **权限管理**：生产环境数据库账号、管理员账号严格管控

### 运维人员配置
- IT 运维人员 1 名：负责服务器维护、备份检查、版本升级
- 业务对接人 1 名：负责用户问题收集、基础数据维护

## P10：ERP 系统拓展延伸应用

### 阶段一：数据回流，补全 ERP 生产执行维度
- 当前痛点：ERP 只有订单起点和终点，缺少中间工序流转过程数据
- 延伸价值：本系统流转数据定期同步回 ERP，补全生产执行全链路
- 典型场景：
  - 生产计划人员可在 ERP 直接查看外协工序进度
  - 成本核算可按工序维度统计停留时长、返工次数等隐性成本
  - 交付预测可基于实际流转速度更准确估算

### 阶段二：计划联动，从执行反馈到计划优化
- 延伸价值：基于历史流转数据，优化 ERP 生产计划与外协排程
- 典型场景：
  - 某厂家某工序平均停留 3 天，排程时自动预留 3 天缓冲期
  - 某工序经常返工，自动触发质量预警并调整后续计划
  - 基于实际流转效率，自动推荐最优外协厂家分配方案

### 阶段三：质量与成本全链路追溯
- 延伸价值：从原材料到成品交付的全链路数据打通
- 典型场景：
  - 成品质量问题，可追溯到每道外协工序的经手人、时间、数量、检验记录
  - 外协成本核算可精确到工序级，识别瓶颈工序与成本洼地
  - 供应商评价可基于真实流转数据量化，不再依赖主观判断

### 实施建议
- 先做 **单向数据同步**（本系统 → ERP），验证价值后再做双向联动
- 优先对接 **订单进度查询、工序状态回写** 两个核心场景
- 试点稳定后再逐步拓展质量、成本等高级场景
