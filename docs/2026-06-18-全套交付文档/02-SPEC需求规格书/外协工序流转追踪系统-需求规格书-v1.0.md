# 外协工序流转追踪系统 — 需求规格书

**版本**：v1.0  
**日期**：2026-06-18  
**状态**：当前已实现版本（基线）

---

## 1. 文档概述

### 1.1 目的
本文档定义外协工序流转追踪系统的功能需求、非功能需求、验收标准与范围边界，作为项目开发、测试、验收的基准依据。

### 1.2 范围
- 适用对象：业务部门、开发团队、测试团队、运维团队
- 覆盖范围：P0 核心流转功能，含扫码录入、订单看板、接收发出、权限隔离、通知预警
- 不覆盖范围：ERP 双向集成、质量追溯、大屏展示（后续 P1-P3 规划）

### 1.3 术语定义
| 术语 | 说明 |
|------|------|
| 工序 | 外协加工的一个环节，如"首道精加工""二道热处理" |
| 流转记录 | 某道工序的接收/发出操作记录，含数量、时间、操作人 |
| 卡点 | 超过 48 小时未处理且有可操作数量的工序 |
| 有效数量 | 扣减退件/返工后的净流转数量 |
| 主厂 | 订单发起方，可查看所有工序 |
| 协作厂 | 外协加工厂家，仅可查看和操作本厂工序 |

## 2. 业务背景与目标

### 2.1 业务背景
外协多厂家间工序交接当前主要依赖纸质记录、口头传达、微信群拍照，存在以下问题：
- 交接记录准确率仅约 85%，容易漏记错记
- 订单进度不透明，不知道零件卡在哪道工序
- 超期/异常发现滞后，平均 3~5 天才发现
- 责任追溯困难，出了问题找不到经手人

### 2.2 建设目标
- 核心目标：每道工序"来有影、去有踪"，流转全链路可追溯
- 效率目标：异常发现时间从 3~5 天缩短到 24 小时内
- 质量目标：交接记录准确率从 85% 提升到 100%

### 2.3 成功度量指标
- 扫码操作成功率 ≥ 99%
- 单条交接操作时间 ≤ 10 秒
- 系统可用性 ≥ 99.5%
- 权限误拦截率 = 0%

## 4. 功能需求规格

### 4.1 FR01：认证与登录

**需求描述**：用户通过手机号验证或账号密码登录系统，系统根据用户角色和所属厂家分配权限。

**功能点**：
1. 支持手机号 + 短信验证码登录
2. 支持用户名 + 密码登录
3. 登录成功后返回 JWT Token，有效期 24 小时
4. 登录失败次数限制：连续 5 次失败后锁定 15 分钟
5. 自动识别用户角色和所属厂家，加载对应权限的菜单和数据

**验收标准**：
- 验证码正确可登录，验证码错误拒绝登录
- 密码正确可登录，密码错误拒绝登录
- Token 过期后访问接口返回 401
- 不同角色登录后看到的菜单和数据范围符合权限矩阵

---

### 4.2 FR02：订单看板

**需求描述**：以列表和卡片形式展示所有订单，展示订单基本信息、工序进度、当前卡点。

**功能点**：
1. 订单列表展示：订单号、产品名称、订单数量、状态、创建时间
2. 订单状态分类：待开始、进行中、已完成
3. 订单详情页：按工序顺序展示每道工序的状态、数量、停留时长、负责人
4. 卡点标识：超过 48 小时未处理且有可操作数量的工序标红并标注"卡点"
5. 风险等级：根据停留时长和可操作数量计算风险等级（正常/提醒/警告/严重）
6. 工序卡片展示：可接收数量、可发出数量、累计接收、累计发出、发出进度百分比

**验收标准**：
- 订单列表按创建时间倒序排列
- 工序进度计算准确：已完成工序数 / 总工序数
- 卡点识别准确：超过 48 小时且有可操作数量的工序正确标红
- 数量展示满足业务约束：发出 ≤ 接收 ≤ 上游可供量
- 首道工序上游可供量 = 订单总数
- 非首道工序上游可供量 = 上道有效发出量

---

### 4.3 FR03：工序接收

**需求描述**：操作员扫码或手动输入记录编号，完成本道工序的零件接收。

**功能点**：
1. 扫码或手动输入记录编号，系统自动带出工序信息和可接收数量
2. 输入接收数量，默认填充最大可接收数量
3. 数量校验：接收数量 ≤ 可接收数量（上游可供量 - 已接收数量）
4. 权限校验：仅该工序所属厂家的用户可操作
5. 提交后生成接收记录，更新工序累计接收数量和状态
6. 操作日志记录：操作人、操作时间、接收数量、操作前后状态

**验收标准**：
- 接收数量超过可接收量时拒绝提交并提示
- 非本厂用户操作时返回 403 权限拒绝
- 提交后工序累计接收数量正确增加
- 操作日志完整记录所有变更
- 接收后订单状态自动更新（如有需要）

---

### 4.4 FR04：工序发出

**需求描述**：操作员扫码或手动输入记录编号，完成本道工序加工后的零件发出。

**功能点**：
1. 扫码或手动输入记录编号，系统自动带出工序信息和可发出数量
2. 输入发出数量，默认填充最大可发出数量
3. 数量校验：发出数量 ≤ 可发出数量（累计接收 - 已发出 - 退件）
4. 权限校验：仅该工序所属厂家的用户可操作
5. 提交后生成发出记录，更新工序累计发出数量和状态
6. 操作日志记录：操作人、操作时间、发出数量、操作前后状态

**验收标准**：
- 发出数量超过可发出量时拒绝提交并提示
- 非本厂用户操作时返回 403 权限拒绝
- 提交后工序累计发出数量正确增加
- 操作日志完整记录所有变更
- 全部发出后工序状态更新为"已完成"

---

### 4.5 FR05：卡点与风险预警

**需求描述**：系统自动识别工序卡点，计算风险等级，生成预警通知。

**功能点**：
1. 卡点识别算法：工序停留时长 > 48 小时 且 有可操作数量（可接收 > 0 或 可发出 > 0）
2. 风险等级计算规则：
   - 正常：≤ 24 小时 或 无可操作数量
   - 提醒：24~48 小时 且 有可操作数量
   - 警告：48~72 小时 且 有可操作数量
   - 严重：> 72 小时 且 有可操作数量
3. 卡点工序在看板中醒目标识
4. 卡点自动生成通知推送给相关厂家操作员和管理员

**验收标准**：
- 卡点识别准确，不漏判不误判
- 风险等级计算符合规则
- 卡点工序在看板中正确标红
- 卡点生成后对应角色收到通知

---

### 4.6 FR06：通知中心

**需求描述**：集中展示系统通知、待办提醒、风险预警，支持标记已读和跳转。

**功能点**：
1. 通知列表展示：标题、内容、时间、已读/未读状态
2. 未读计数：顶部导航栏显示未读通知数量
3. 标记已读：单条标记已读、全部标记已读
4. 通知分类：系统通知、待办提醒、风险预警
5. 跳转功能：点击通知可跳转到对应订单/工序页面
6. 通知保留：历史通知保留 90 天

**验收标准**：
- 未读计数准确，标记已读后计数减少
- 通知按时间倒序排列
- 点击通知可正确跳转到对应页面
- 90 天前的通知自动清理（或归档）

---

### 4.7 FR07：扫码录入

**需求描述**：通过手机摄像头扫码快速完成工序接收和发出，支持连续扫码批量录入。

**功能点**：
1. 摄像头扫码：调用手机摄像头识别二维码/条码
2. 手动输入兜底：扫码失败时可手动输入记录编号
3. 批量导入：支持离线扫码后批量导入
4. 连续扫码：扫码一次加入清单，可连续扫码多个记录
5. 数量编辑：扫码后可修改接收/发出数量
6. 异常处理：重复扫码、无效编码、跨厂扫码等异常场景提示
7. 统一提交：确认清单后一次性提交所有操作
8. 操作结果：提交后显示成功/失败数量和明细

**验收标准**：
- 正常光照下扫码识别成功率 ≥ 95%
- 连续扫码 10 条无卡顿
- 重复扫码自动识别并提示
- 无效编码提示"记录不存在"
- 跨厂扫码提示"无权操作其他厂家工序"
- 提交后所有操作原子性：全部成功或全部失败

---

### 4.8 FR08：退件与返工

**需求描述**：记录工序退件和返工操作，扣减有效数量，生成返工流转记录。

**功能点**：
1. 退件记录：记录退件数量、原因、时间、操作人
2. 数量扣减：退件数量从该工序有效数量中扣减
3. 返工流转：返工完成后重新进入流转流程
4. 退件原因可选：质量问题、数量不符、其他
5. 返工后可重新接收，继续流转

**验收标准**：
- 退件后有效接收数量 = 原接收数量 - 退件数量
- 退件后可发出数量同步扣减
- 返工完成后可重新接收并继续流转
- 退件记录完整可查

---

### 4.9 FR09：基础数据管理

**需求描述**：管理员维护厂家、工序、用户等基础数据。

**功能点**：
1. 厂家管理：新增、编辑、禁用厂家，维护厂家名称、联系人、电话
2. 用户管理：新增、编辑、禁用用户，维护用户名、密码、角色、所属厂家
3. 工序管理：维护工序名称、排序、所属厂家、标准工时
4. 订单管理：创建订单，维护订单基本信息和工序列表
5. 数据导出：基础数据和流转记录可导出 Excel

**验收标准**：
- 基础数据增删改查功能正常
- 禁用的厂家/用户无法登录和操作
- 工序排序正确影响看板展示顺序
- 导出的 Excel 格式正确、数据完整

---

### 4.10 FR10：导出与报表

**需求描述**：导出流转记录和统计报表，支持按时间、厂家、订单等维度筛选。

**功能点**：
1. 流转记录导出：按订单、时间、厂家筛选导出 Excel
2. 工序效率报表：各工序平均停留时长、异常率统计
3. 厂家效率报表：各厂家平均处理时长、返工率统计
4. 订单进度报表：订单完成率、卡点数量统计
5. 导出格式：Excel、CSV

**验收标准**：
- 筛选条件组合正确生效
- 导出数据准确完整
- Excel 格式可正常打开和编辑
- 大数量导出（>10000 条）无超时

## 7. 接口需求规格

### 7.1 前后端 API 契约原则

1. RESTful 风格，HTTP 方法语义明确
2. 统一响应格式：`{code, message, data}`
3. 统一错误码：400 参数错误、401 未认证、403 无权限、404 不存在、500 服务器错误
4. 分页参数统一：`page, page_size`
5. 排序参数统一：`sort_by, sort_order`
6. 所有接口支持跨域（CORS）

### 7.2 核心 API 清单

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/auth/send-sms` | POST | 发送短信验证码 |
| `/api/auth/login` | POST | 登录（验证码/密码） |
| `/api/kanban/orders` | GET | 订单看板列表 |
| `/api/kanban/orders/{order_id}/processes` | GET | 订单工序列表 |
| `/api/records/detail/{record_id}` | GET | 流转记录详情 |
| `/api/records/receive` | POST | 工序接收 |
| `/api/records/ship` | POST | 工序发出 |
| `/api/records/scan` | POST | 扫码校验 |
| `/api/notifications` | GET | 通知列表 |
| `/api/notifications/read` | POST | 标记已读 |
| `/api/admin/users` | GET/POST | 用户管理 |
| `/api/admin/factories` | GET/POST | 厂家管理 |
| `/api/export/records` | GET | 流转记录导出 |

### 7.3 ERP 集成接口预留

- 订单同步接口：ERP → 本系统，创建和更新订单
- 进度回写接口：本系统 → ERP，回写工序进度和状态
- 基础数据同步：ERP → 本系统，同步厂家、工序、物料主数据

## 8. 验收标准与口径

### 8.1 功能验收标准

| 功能模块 | 验收项 | 通过标准 |
|---------|-------|---------|
| 认证登录 | 验证码登录 | 验证码正确可登录，错误拒绝 |
| | 密码登录 | 密码正确可登录，错误拒绝 |
| | 权限控制 | 跨厂操作返回 403，数据范围正确 |
| 订单看板 | 列表展示 | 订单展示完整，状态正确 |
| | 数量展示 | 发出 ≤ 接收 ≤ 上游可供，无不一致 |
| | 卡点识别 | 超 48 小时且有可操作数量的工序正确标红 |

## 9. 范围边界与限制

### 9.1 当前版本已实现范围

✅ FR01 认证与登录（验证码 + 密码双模式）  
✅ FR02 订单看板（列表、详情、工序状态、卡点标识）  
✅ FR03 工序接收（扫码/手动输入、数量校验、权限校验）  
✅ FR04 工序发出（扫码/手动输入、数量校验、权限校验）  
✅ FR05 卡点与风险预警（卡点识别、风险等级计算）  
✅ FR06 通知中心（列表、未读计数、标记已读）  
✅ FR07 扫码录入（连续扫码、批量录入、异常处理）  
✅ FR09 基础数据管理（用户、厂家管理）  

### 9.2 当前版本未实现范围

🔲 FR08 退件与返工（P1 规划）  
🔲 FR10 导出与报表（P1 规划，仅基础导出可用）  
🔲 ERP 双向集成（P2 规划）  
🔲 质量追溯拓展（P2 规划）  
🔲 高级分析与大屏（P3 规划）  

### 9.3 已知限制

1. 扫码功能依赖手机摄像头权限，部分老旧手机可能不支持
2. 离线扫码仅支持缓存，不支持完整离线操作
3. 通知推送仅支持站内通知，不支持短信/微信推送（后续可扩展）
4. 当前仅支持 2~3 家试点厂家，大规模接入需性能压测
