**版本**：v1.0  
**日期**：2026-06-18

## 场景 1：新订单创建与工序初始化流程

### 流程说明
1. 管理员在后台创建订单，填写订单基本信息和工序列表
2. 系统为每道工序生成一条 `process_records` 记录
3. 首道工序自动标记为 `entry_lock`（入口锁）
4. 后续工序初始状态为 `pending`

### 初始化规则
- 每条记录生成唯一 `record_id`，格式：`{order_id}_R{process_index}`
- 首道工序（process_index=1）的 `lock_type = 'entry_lock'`
- 所有记录初始 `total_receive_qty = 0`, `total_ship_qty = 0`
- 订单状态初始为 `pending`

---

## 场景 2：首道工序接收与发出完整流程

### 接收流程
1. 操作员扫码或输入 record_id
2. 系统校验：
   - 记录存在
   - 当前用户厂家 == 工序所属厂家
   - `available_receive_qty > 0`（上游可供量 - 已接收）
3. 首道工序的上游可供量 = 订单总数
4. 更新 `total_receive_qty += 接收数量`
5. 记录操作日志
6. 如果检测到上道 record 是 entry_lock，自动升级为 relation_lock（P0 Bug Fix）

### 发出流程
1. 操作员扫码或输入 record_id
2. 系统校验：
   - 记录存在
   - 当前用户厂家 == 工序所属厂家
   - `available_ship_qty > 0`（已接收 - 已发出 - 退件）
3. 更新 `total_ship_qty += 发出数量`
4. 记录操作日志
5. 自动更新订单状态（如果有流转则为 in_progress）

## 场景 3：中间道工序跨厂家交接流程

### 上道发出 → 本道接收
1. 上道工序（index=N）发出后，本道工序（index=N+1）的可接收数量 = 上道有效发出数量
2. 本道操作员扫码，系统校验厂家权限
3. 接收数量校验：接收数量 ≤ 上道有效发出数量 - 本道已接收数量
4. 接收成功后，本道累计接收数量增加
5. 本道可发出数量 = 本道累计接收 - 本道累计发出 - 本道退件

### 数量一致性保障
- 上道有效发出 = 上道累计发出 - 上道退件
- 本道最大可接收 = 上道有效发出
- 本道最大可发出 = 本道累计接收 - 本道退件
- 约束：本道累计发出 ≤ 本道累计接收 ≤ 上道有效发出

## 场景 4：超期卡点识别与通知触发算法

### 卡点识别规则
```
卡点 = (停留时长 > 48 小时) AND (可接收数量 > 0 OR 可发出数量 > 0)
```

### 停留时长计算
```
if 状态 = pending（从未接收过）:
    停留时长 = 当前时间 - 记录创建时间
elif 状态 = received（已接收未发出）:
    停留时长 = 当前时间 - 最后接收时间
else:
    停留时长 = 0（已完成，不计算卡点）
```

### 风险等级计算
```
if 无可操作数量:
    风险等级 = normal
elif 停留时长 ≤ 24 小时:
    风险等级 = normal
elif 停留时长 ≤ 48 小时:
    风险等级 = remind
elif 停留时长 ≤ 72 小时:
    风险等级 = warning
else:
    风险等级 = serious
```

### 通知触发
- 风险等级 ≥ warning 时，自动给该厂家管理员和操作员发送通知
- 通知内容："工序 {process_name} 已停留 {X} 小时未处理，请及时操作"
- 同一条记录 24 小时内不重复发送通知

## 场景 5：可接收/可发出数量计算逻辑

### 可接收数量
```python
if 是首道工序:
    upstream_available = order.total_qty
else:
    prev_record = 上道工序记录
    upstream_available = prev_record.total_ship_qty - prev_record.return_qty

available_receive = max(0, upstream_available - current_record.total_receive_qty)
```

### 可发出数量
```python
effective_receive = current_record.total_receive_qty - current_record.return_qty
available_ship = max(0, effective_receive - current_record.total_ship_qty)
```

### 展示数量（Clamp 逻辑）
历史测试数据可能存在毛数量超过订单量的情况，展示层做 clamp：
```python
display_receive = min(total_receive_qty, order.total_qty)
display_ship = min(total_ship_qty, display_receive)
```

## 场景 6：权限判定与跨厂操作拦截规则

### 权限判定流程
```python
def can_operate(user, record_factory_id):
    if user.role == 'admin':
        return True, None
    if user.factory_id != record_factory_id:
        return False, "您不属于该厂家，无权操作"
    return True, None
```

### 拦截点
1. **扫码校验**：`/scan` 接口返回前校验，跨厂直接返回 403
2. **接收提交**：`/receive` 接口前置校验
3. **发出提交**：`/ship` 接口前置校验
4. **记录详情**：`/detail/{record_id}` 接口前置校验

## 场景 7：退件/返工后有效数量重算逻辑

### 退件后
- `return_qty += 退件数量`
- `available_ship = total_receive_qty - return_qty - total_ship_qty`
- 退件后可能出现：可发出数量 = 0（如果全部退完）

### 返工后
- 返工重新接收：`total_receive_qty += 返工数量`
- `return_qty` 不变（保留历史退件记录）
- 可发出数量重新增加

## 场景 8：订单完结状态判定规则

### 订单状态自动更新
```python
def _update_order_status(order_id):
    records = 该订单所有工序记录
    all_completed = all(r.record_status == 'completed' for r in records)
    
    if all_completed:
        new_status = 'completed'
    elif any(r.total_receive_qty > 0 or r.total_ship_qty > 0 for r in records):
        new_status = 'in_progress'
    else:
        new_status = 'pending'
    
    if order.order_status != new_status:
        更新订单状态并记录日志
```

### 触发时机
- 每次接收成功后
- 每次发出成功后
- 每次退件/返工后
