## 1. 整体架构

### 1.1 分层架构
```
┌─────────────────────────────────┐
│     前端层 (Vue3 + Vant)        │
│  ┌───────────────────────────┐  │
│  │  页面层：Login/Kanban/Scan │  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │  状态层：Pinia + Axios     │  │
│  └───────────────────────────┘  │
└──────────────┬──────────────────┘
               │ HTTP/HTTPS
┌──────────────▼──────────────────┐
│     后端层 (FastAPI)            │
│  ┌───────────────────────────┐  │
│  │  路由层：Routers           │  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │  业务层：Services          │  │
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │  数据层：SQLAlchemy ORM    │  │
│  └───────────────────────────┘  │
└──────────────┬──────────────────┘
               │
┌──────────────▼──────────────────┐
│     数据层 (MySQL 8.0)          │
│  订单、工序、流转记录、用户      │
└─────────────────────────────────┘
```

### 1.2 核心设计原则
1. **权限后置**：所有写入操作在 Service 层做权限校验，不依赖前端拦截
2. **数量三原则**：发出 ≤ 接收 ≤ 上游可供量，三层校验（前端输入 → 后端业务 → DB事务）
3. **操作可追溯**：所有写入操作都生成 action_log，完整记录变更前后
4. **展示与存储分离**：DB 存储原始数据，API 层计算有效数量，不清洗历史数据
5. **移动端优先**：前端全部按移动端设计，响应式适配桌面端

## 2. 技术选型说明

| 技术 | 选型原因 | 替代方案 |
|------|---------|---------|
| FastAPI | 自动生成 API 文档、类型安全、性能优秀 | Flask、Django REST |
| SQLAlchemy 2.0 | ORM 成熟、防止 SQL 注入、迁移友好 | 原生 SQL、Peewee |
| MySQL 8.0 | 事务支持、关系型数据适合流转业务 | PostgreSQL |
| Vue 3 + Composition API | 移动端生态成熟、Vant 组件库完善 | React、Angular |
| Vant 4 | 移动端组件丰富、扫码、表单、列表等组件开箱即用 | Element Plus、AntD Mobile |
| Pinia | Vue 官方推荐、TypeScript 友好 | Vuex |
| @zxing/browser | 纯 JS 扫码库、兼容性好 | QuaggaJS |
| Docker Compose | 部署简单、环境一致性 | K8s（过重） |

## 3. 模块划分与职责

### 3.1 后端模块

| 模块 | 文件路径 | 核心职责 |
|------|---------|---------|
| 认证模块 | `routers/auth.py` + `services/auth_service.py` | 发送验证码、登录、JWT 生成与校验 |
| 看板模块 | `routers/kanban.py` + `services/kanban_service.py` | 订单看板、工序统计、卡点识别、风险计算 |
| 流转记录模块 | `routers/records.py` + `services/record_service.py` | 接收、发出、扫码校验、操作日志 |
| 通知模块 | `routers/notifications.py` + `services/notification_service.py` | 通知列表、未读计数、标记已读 |
| 管理模块 | `routers/admin.py` + `services/user_service.py` | 用户管理、厂家管理、基础数据维护 |
| 导出模块 | `routers/export.py` + `services/export_service.py` | 流转记录导出 |
| 核心模块 | `core/` | 配置、数据库连接、JWT 安全、依赖注入 |
| 数据模型 | `models/` + `schemas/` | SQLAlchemy 模型 + Pydantic 请求/响应模型 |

### 3.2 前端模块

| 模块 | 文件路径 | 核心职责 |
|------|---------|---------|
| 页面层 | `src/views/*.vue` | 各业务页面组件 |
| 组件层 | `src/components/*.vue` | 可复用公共组件（工序卡片等） |

| 工具层 | `src/utils/*.ts` | 通用工具函数 |

## 4. 权限设计方案

### 4.1 权限模型
- RBAC（基于角色的访问控制）+ 数据范围隔离
- 角色定义：admin、factory_admin、factory_operator
- 数据范围：用户绑定 factory_id，非 admin 只能操作本厂数据

### 4.2 权限校验流程
```
请求 → Token 解析 → 获取当前用户 → 
  if 是 admin: 允许全部操作
  else: 校验操作目标的 factory_id == 当前用户.factory_id
    → 匹配: 允许操作
    → 不匹配: 返回 403 "无权操作其他厂家数据"
```

### 4.3 关键校验点
1. **看板列表**：非 admin 只返回包含本厂工序的订单
2. **工序操作**：接收/发出前必须校验 `process.factory_id == 当前用户.factory_id`
3. **扫码校验**：`/scan` 接口返回前校验可见性
4. **记录详情**：`check_record_visible()` 统一校验
