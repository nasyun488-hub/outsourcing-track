## 本轮发现的问题

### 问题：工序详情数量展示超出订单数量

页面：`/kanban/DEMO_PENDING_001`

复测发现第一道工序曾显示：
- 订单数量：80
- 累计接收：80
- 累计发出：100
- 文案：`上道发出 80，本次已收 80，本次已发 100`

这会造成“发出数量超过订单数量”的业务误导。

### 根因

复测环境数据库中保留了历史操作后的毛数量：
- `DEMO_PENDING_R1.total_receive_qty = 80`
- `DEMO_PENDING_R1.total_ship_qty = 100`

同时存在退件流水 20。旧展示逻辑直接显示毛数量，没有按退件有效数量和业务上限进行展示防御。

## 修复内容

### 后端修复

修改文件：
- `backend/app/services/kanban_service.py`
- `backend/app/services/record_service.py`

修复点：
1. Kanban API 增加有效数量计算：扣减退件数量。
2. 按业务上限 clamp：`发出 <= 接收 <= 上游可供量`。
3. 首道工序上游可供量按订单总数计算。
4. 非首道工序上游可供量按上道有效发出量计算。
5. `available_receive_qty` / `available_ship_qty` 使用修正后的安全数量。
6. 记录详情、接收页、发出页的运行态数量同步使用安全数量。
7. 接收前置校验改为检查上道有效发出量。

### 前端修复

修改文件：
- `frontend/src/components/ProcessCard.vue`
- `frontend/src/views/ReceivePage.vue`
- `frontend/src/views/ShipPage.vue`

修复点：
1. 工序卡片展示层增加数量 clamp 防御。
2. 发出进度、累计接收、累计发出、提示文案均使用安全数量。
3. 接收页/发出页展示“上道已发、本道已收、可接收、可发出”时避免显示异常毛数量。
