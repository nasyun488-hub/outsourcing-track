# 扫码录入购物车式优化验证报告

日期：2026-06-16  
项目：外协工序流转追踪系统

## 结论

已完成本轮扫码录入优化并部署前端：批量录入已改为“类似超市购物扫码”的连续扫码清单模式；手机扫码功能已接入相机连续识别与拍照/相册兜底识别。

> 边界说明：本轮完成代码、构建、部署、浏览器 DOM 操作验证；未在真实手机摄像头上做像素级实拍验收。

## 本轮改动

### 1. 购物车式连续扫码录入

修改文件：`frontend/src/views/ScanPage.vue`

已实现：

- 扫码枪扫码后不再自动跳转接收/发出页面。
- 每扫一次，当前页面新增一行清单记录。
- 每行显示：二维码、操作类型、来源、提示信息、工序、可接收量、可发出量。
- 默认数量自动取业务可用数量：
  - 接收：`available_receive_qty`
  - 发出：`available_ship_qty`
- 数量输入框可修改。
- 每行可删除。
- 底部统一提交“可录入记录”。
- 提交时按扫码判断结果自动调用：
  - `receive()`：接收录入
  - `ship()`：发出录入
- `view/not_found` 类型会展示但不可提交，避免误录。

### 2. 批量录入体验调整

批量入口由“批量解析后跳转/历史展示”调整为“批量加入录入清单”：

- 支持一行一个二维码。
- 支持逗号、空格、制表符分隔。
- 每个码值依次创建清单行。
- 操作员可逐行改数量、删行，再统一提交。

### 3. 手机扫码功能

已实现：

- `@zxing/browser` 相机连续扫码。
- 手机相机 Tab 显示“打开相机连续扫码”。
- 识别成功后加入清单，不自动跳走。
- 同一二维码短时间防重复加入。
- 增加“拍照/相册识别”兜底入口：
  - `accept="image/*"`
  - `capture="environment"`
  - `decodeFromImageUrl()` 识别图片二维码

## 修复过程中的注意点

子任务曾临时生成 `frontend/.npmrc`：

```ini
script-shell=/usr/bin/bash
```

该配置会导致 `node:18-alpine` Docker 构建失败，因为 Alpine 镜像内没有 `/usr/bin/bash`。已删除该文件，Docker 构建恢复通过。
