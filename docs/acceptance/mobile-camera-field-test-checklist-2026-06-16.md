# P0 手机摄像头扫码现场验收清单（2026-06-16）

> 重要声明：本清单和 HTTPS/样张/页面提示仅表示已经具备现场验收支撑，**未等于真机已通过**。实际结论必须由验收人员在真实手机、真实浏览器、局域网环境下执行并记录。

## 前置准备

1. 启动后端、数据库和 HTTPS 前端服务：
   - 准备本地自签或局域网证书文件：`certs/local.crt`、`certs/local.key`（不要提交真实密钥）。
   - 使用 `docker compose -f docker-compose.yml -f docker-compose.https.yml up --build` 启动。
2. 确认手机与部署机器在同一局域网。
3. 手机浏览器访问：`https://<局域网IP>:8443/scan`。
4. 如使用自签证书，按浏览器提示完成临时信任/继续访问。
5. 进入扫码页后选择“手机扫码”，点击“打开相机连续扫码”，并**允许摄像头权限**。

## 样张扫码

样张目录：`docs/acceptance/mobile-scan-samples/`。

必须逐一扫码并记录结果：

- `record_DEMO_PENDING_R1`：验证待接收记录可加入清单并提交接收。
- `record_DEMO_RECEIVED_R1`：验证已接收记录可加入清单并提交发出。
- `bad_code_for_field_test`：验证无效码进入异常区、不可提交、提示清晰。

## 提交与回查

1. 对可提交记录确认数量后点击提交。
2. 提交后进行 API/DB 回查：
   - API 回查：调用记录详情或列表接口，确认状态、接收数量、发出数量与页面提交一致。
   - DB 回查：直接查询对应记录表，确认数据库状态与 API 返回一致（记录 SQL、截图或查询输出）。
3. 确认重复扫码、异常码、拍照/相册兜底路径没有破坏清单状态。

## 浏览器与控制台检查

1. 验收期间打开移动端调试或浏览器远程调试。
2. 确认控制台无 JS error。
3. 若相机无法启动，记录浏览器、系统版本、HTTPS 证书状态、浏览器权限、摄像头是否被其他应用占用。
