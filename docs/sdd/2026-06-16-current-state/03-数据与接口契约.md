| 表 | 作用 | 关键字段 |
|---|---|---|
| `factories` | 厂家 | `factory_id`、`factory_name`、`factory_type`、`status` |

| `ship_batches` | 发出批次 | `batch_id`、`record_id`、`user_id`、`ship_qty`、`batch_no` |
| `return_records` | 退件记录 | `return_id`、`from_record_id`、`to_record_id`、`return_qty`、`return_reason` |

## 3. 前后端契约

1. 前端 API 字段必须对照后端真实返回。
2. token 后续请求必须带 `Authorization: Bearer <token>`。
3. `record_id` / `order_id` 均保持字符串，不转数字。
4. 导出接口按二进制 Blob 处理。
5. 扫码页数量上限必须使用后端返回的可用数量。

## 4. 数量与状态规则

| 场景 | 规则 |
|---|---|
| 接收 | 数量 > 0 且不超过可接收数量 |
| 发出 | 数量 > 0 且不超过可发出数量 |
| 退件 | 影响上下道净数量，并写入 `return_records` |
| 扫码异常 | 无权限/无效码/无可操作数量进入异常区，不阻断继续扫码 |

## 5. DB 回查规范

- 查询中文必须使用 `--default-character-set=utf8mb4`。
- 脚本不得硬编码数据库密码。
- 交叉验证必须包含：DB 基线、API 调用、API 响应、DB 回查、通知/权限/数量比对。
